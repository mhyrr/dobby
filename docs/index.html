Dobby

A house elf for your Home Assistant. Anyone at home can ask it for things in plain words, and it does them.

You set up Home Assistant. The rest of the house asks you to change the thermostat. Dobby gives them someone else to ask: one shared thread, always open, with a housemate in it who runs things. "Set it to 70." "Make it cozy." "Send the vacuum out." "I want it at 70 by eight on weekdays." Dobby does what you said, says what it did, and asks when it is not sure.

What that gets you, on top of a working Home Assistant:

  • Anyone at home can run the house. Kids included. No app to learn, no dashboard, no automation editor. The kitchen tablet and every phone open the same thread, and whoever speaks, their name goes on what changed. When somebody turns the heat up, the thread says who.
  • It keeps its word. Say "70 by eight on weekdays" once and it happens at eight on weekdays, with no AI in the loop, so it happens when the model is down too. And "set to 70" means exactly that: the thermostat took the command. Dobby never tells you the room is warm. The board shows you that, when Home Assistant reports it. You stop checking.
  • It asks before it guesses. Two thermostats and you said "the thermostat"? It asks which. A device it does not have, it says so. A number the house does not allow, it declines and gives you the reason. Nothing happens to your house that nobody asked for.
  • Setup is a conversation. Tell Dobby what you have, and it finds the devices in Home Assistant and proposes them. One yes adopts the lot. Or point Claude Code, or any MCP client, at Dobby and let the AI you already use do it.

You describe the house in one file and give Dobby a voice in another. Home Assistant keeps running the devices. Dobby runs the house.

What you need

  • A Home Assistant you can reach, and a long-lived access token. In HA: your profile → Security → Long-lived access tokens. It is shown once. Copy it straight into your environment.
  • Elixir 1.18 or later, and PostgreSQL. mix setup installs the rest.
  • A model API key. An Anthropic key works out of the box. system.model in the house file switches to any other provider.
  • mDNS, so the house can open dobby.local. macOS has it. On Linux, install Avahi (avahi-daemon and avahi-utils).

The five-minute path

Clone, set up, copy the example house file, and edit it. The example has a comment on every line you might change.

git clone https://github.com/mhyrr/dobby.git && cd dobby
mix setup
cp config/homes/example.yaml config/homes/my-house.yaml
# edit it: your HA's address, your devices

Export the credentials, then check the wiring before you trust it with an evening.

export DOBBY_HA_URL=http://homeassistant.local:8123
export DOBBY_HA_TOKEN=...
export ANTHROPIC_API_KEY=...

DOBBY_HOME_MANIFEST=config/homes/my-house.yaml mix dobby.ha.verify

What you should see

[info] connected to Home Assistant 2026.8.2 at http://homeassistant.local:8123 home "my-house" with 2 device(s) %{ id: "light:living_room", name: "living room light", type: :light, available: true, power: :on, brightness_percent: 71 } %{ id: "thermostat:hall", name: "hall thermostat", type: :thermostat, available: true, target_temperature_f: 70, min_temperature_f: 60, max_temperature_f: 78, current_temperature_f: 72, hvac_mode: :cool } initial state sync: ok

Every device available: true with readings. If one stays unavailable, its entity id is wrong, and the task names it.

Start it and open it.

DOBBY_HOME_MANIFEST=config/homes/my-house.yaml mix phx.server

What you should see

hall thermostat70°Cooling
living room light71%Set
office printerAwake

At http://localhost:4000/: your devices on the board, each with a reading and a word, and the thread below. For a moment after boot a device reads NOT KNOWN. The first sync from Home Assistant fills it in.
